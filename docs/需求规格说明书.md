| 文档版本 | 修订日期   | 说明     |

## 1. 引言

### 1.1 文档目的

本文档描述「智能数据分析系统」的产品范围、功能需求与非功能需求，作为产品设计、开发实现与验收测试的依据。

### 1.2 项目概述

系统面向数据分析场景：用户通过自然语言提问，后端基于大模型将意图转化为 SQL，在 SQLite 上执行查询，并将结果以结构化数据返回；前端在对话界面展示回答，并在独立区域实时展示可视化图表，形成「问—答—图」一体化体验。

### 1.3 术语与缩写

| 术语 | 说明 |
|------|------|
| NL2SQL | Natural Language to SQL，自然语言到 SQL 的生成与执行流程 |
| 百炼 | 阿里云大模型服务平台，用于接入 Qwen 等模型 |
| SSE | Server-Sent Events，服务端推送事件，常用于流式响应 |
| 会话 | 一次独立的对话线程，包含多条用户与助手消息 |

### 1.4 参考与约束

- 大模型：阿里云百炼 **Qwen3**（具体模型名称以控制台可用列表为准）。
- 后端：**LangChain** + **FastAPI**。
- 数据库：**SQLite**（区分「业务分析数据」与「应用元数据」的存储策略由实现阶段确定，见第 5 节）。
- 前端：**React**，三栏布局（左：会话管理，中：问答，右：图表）。

## 2. 目标与范围

### 2.1 建设目标

1. 降低数据分析门槛：非 SQL 用户可通过中文（或可扩展为多语言）提问获取数据结果。
2. 可追溯：用户可查看系统生成的 SQL，便于核对与教学演示。
3. 可对话：支持多轮对话，利用上下文理解指代（如「上面那个部门」）。
4. 可视化：查询结果自动映射为合适图表，辅助理解。

### 2.2 范围内（Must）

- 接入百炼 Qwen3，完成服务端调用（含密钥管理与配置）。
- NL2SQL：根据自然语言与 schema 上下文生成 SQL，执行并返回列名与行数据。
- 会话的创建、列表、删除（及可选的重命名）；消息持久化。
- 多轮上下文记忆（与会话绑定）。
- 前端三栏 UI 与图表展示；查询成功后图表区展示与数据一致。

### 2.3 范围外（本期可不实现）

- 多租户与完整账号体系（若演示需要，可采用固定匿名用户或简单口令）。
- 任意写库、删表等高危操作（默认只读查询）。
- 非 SQLite 的其他数据库引擎（可预留扩展点，但不作为本期交付）。

## 3. 用户角色与场景

### 3.1 角色

| 角色 | 描述 |
|------|------|
| 数据分析用户 | 使用系统进行提问、查看 SQL、查看图表的最终用户 |

### 3.2 典型场景

1. **新建会话并提问**：用户新建会话，输入「各月份销售额是多少」，系统返回文字解释、SQL、表格数据，右侧出现柱状图或折线图。
2. **多轮追问**：用户继续问「只保留前三个月」，系统结合上文生成新 SQL 并更新图表。
3. **会话切换**：用户从左侧切换到历史会话，中间展示历史消息，右侧展示该会话最近一次查询结果对应的图表（或明确规则见 4.3.3）。
4. **删除会话**：用户删除某会话后，列表与存储中不再展示该会话（实现需符合数据删除策略）。

## 4. 功能需求

### 4.1 大模型接入（FR-LM）

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| FR-LM-01 | 服务端通过阿里云百炼调用 Qwen3 完成对话生成 | 配置有效 API Key 后，接口可返回模型文本，错误时有明确错误信息（不落库密钥） |
| FR-LM-02 | 模型参数（如 temperature、max_tokens）可配置 | 通过环境变量或配置文件调整，文档中说明默认值 |
| FR-LM-03 | 支持流式输出（推荐） | 助手回复可分段到达前端；若首期仅非流式，需在文档中标注为阶段目标 |

### 4.2 数据库与 NL2SQL（FR-SQL）

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| FR-SQL-01 | 系统能读取 SQLite 中业务库的表结构信息，并注入 NL2SQL 流程 | 生成的 SQL 所引用的表、列与真实 schema 一致（在合理提问下） |
| FR-SQL-02 | 根据用户自然语言生成 SQL 并执行 | 返回 `columns`、`rows`（或等价结构），以及实际执行的 `sql` 文本 |
| FR-SQL-03 | 默认仅允许只读查询 | 拒绝 DROP/DELETE/UPDATE 等非查询类语句（或按白名单策略）；多语句执行被禁止 |
| FR-SQL-04 | 查询保护 | 设置超时与最大返回行数，避免拖垮服务；超大结果可截断并提示 |
| FR-SQL-05 | 执行失败时 | 返回用户可理解的说明，不暴露服务器路径与堆栈细节（开发模式可开关详细日志） |

### 4.3 会话与记忆（FR-SESS）

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| FR-SESS-01 | 支持创建会话 | 生成唯一 `session_id`，可设置默认标题（如「新对话」或首句摘要） |
| FR-SESS-02 | 支持会话列表 | 展示标题、更新时间；可切换当前会话 |
| FR-SESS-03 | 支持删除会话 | 删除后会话及关联消息不再出现在 UI；持久化层一并删除或标记删除（需一致） |
| FR-SESS-04 | 消息持久化 | 用户与助手消息均可保存；助手消息宜保存 `sql`、查询结果摘要等元数据（JSON 字段）便于恢复图表 |
| FR-SESS-05 | 上下文记忆 | 同一会话内多轮请求携带近期对话历史或 LangChain Memory；指代类问题能参考上文 |
| FR-SESS-06 | 会话与 NL2SQL 协同 | 生成 SQL 时除历史外仍必须结合当前 schema，避免「记得上文但写错表名」 |

### 4.4 前端界面（FR-UI）

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| FR-UI-01 | 布局：左侧会话管理、中间问答、右侧图表 | 三栏在常见桌面宽度下可用；窄屏可降级为抽屉或 Tab（可选） |
| FR-UI-02 | 中间区展示对话列表与输入框 | 支持发送、加载中状态；助手消息可展示自然语言与可折叠 SQL |
| FR-UI-03 | 右侧根据查询结果渲染图表 | 数值/类别/时间等类型有基础图表策略；无法作图时以表格为主并提示 |
| FR-UI-04 | 数据一致性 | 右侧展示与「当前会话最近一次带查询结果的消息」一致；切换会话时更新 |
| FR-UI-05 | 实时性 | 流式场景下边生成边展示；非流式则在整包返回后更新图表 |

### 4.5 后端服务（FR-API）

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| FR-API-01 | 提供 RESTful API 供前端调用 | 会话与消息的增删查；发送消息触发 LLM + NL2SQL 流程 |
| FR-API-02 | CORS | 开发环境下允许前端源访问；生产环境可配置允许域名 |
| FR-API-03 | 健康检查 | 提供 `/health` 或等价接口便于部署探活 |

## 5. 数据需求

### 5.1 业务分析库（SQLite）

- 存放待分析的业务表（如销售、订单、用户行为等），由部署方提供或随示例数据初始化。
- NL2SQL 仅针对该库；表结构变更后应能重新加载 schema 描述。

### 5.2 应用元数据（SQLite）

建议至少包含：

- **sessions**：`id`、`title`、`created_at`、`updated_at` 等。
- **messages**：`id`、`session_id`、`role`（user/assistant）、`content`、`meta`（JSON，可选存 `sql`、`chart_type`、结果摘要等）。

---

## 6. 非功能需求

### 6.1 安全

- API Key、数据库路径等敏感配置仅服务端持有，不得写入前端代码仓库。
- SQL 执行必须经过安全策略（见 FR-SQL-03、FR-SQL-04）。

### 6.2 性能（建议值，可按部署调整）

- 单次对话接口在模型与查询正常时，P95 延迟目标由部署环境决定；查询必须设超时。
- 前端首屏加载与图表渲染无明显卡顿（数据量在合理范围内）。

### 6.3 可维护性

- 后端分层清晰：路由、LLM 与链、SQL 执行、存储分离。
- 依赖版本固定（`requirements.txt` / `pyproject.toml` 与 `package-lock` 等）。

### 6.4 兼容性

- 浏览器：现代 Chrome / Edge / Firefox 最新两个大版本。
- Python 与 Node 版本在 README 中明确说明。

## 7. 接口需求（概要）

实现阶段需细化路径与字段，本期需求仅约定能力：

| 能力 | 方法/说明 |
|------|-----------|
| 创建会话 | `POST /api/sessions` |
| 会话列表 | `GET /api/sessions` |
| 删除会话 | `DELETE /api/sessions/{id}` |
| 可选更新会话标题 | `PATCH /api/sessions/{id}` |
| 发送消息 | `POST /api/sessions/{id}/messages`（响应含 `reply`、`sql`、`data` 等） |
| 历史消息 | `GET /api/sessions/{id}/messages` |
| 流式消息（可选） | `GET` 或 `POST` + SSE，事件类型与数据格式在接口文档中定义 |

## 8. 验收与测试要点

1. 在无密钥或错误密钥时，接口返回明确错误，前端不崩溃。
2. 典型 NL2SQL 用例：单表聚合、多表连接、带条件与排序；结果与直接执行 SQL 一致。
3. 恶意或越权 SQL 被拒绝。
4. 新建会话 → 多轮对话 → 切换会话 → 删除会话，数据与 UI 一致。
5. 有查询结果时会话内图表与数据一致。

---

## 9. 风险与假设

| 类型 | 说明 |
|------|------|
| 假设 | 百炼 API 可用且额度充足；业务 SQLite 表结构稳定或有变更通知机制 |
| 风险 | NL2SQL 在复杂 schema 下可能生成错误 SQL，需通过提示工程与校验缓解 |
| 风险 | 流式 + 结构化字段混合时，前后端协议需约定清晰，避免解析错误 |
